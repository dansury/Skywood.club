# spec/frontend.md

Статический фронтенд в корне сайта. Без сборки. Шрифты — Google Fonts (Manrope, Unbounded).

## index.html — лендинг

Секции: header (fixed) → hero (видео + параллакс) → marquee → products → parallax-блок → why (преимущества) → compare → how (доставка/оплата) → reviews → faq → finale → footer. Плюс корзина-drawer, модалка товара, модалка чекаута, toast.

Hero: `<video autoplay muted loop playsinline>` c `poster`, источник `/assets/video/hero.mp4`. Параллакс-фоны — `background-attachment:fixed` + `data-parallax` на hero-контенте.

## css/styles.css

Тёмная лесная палитра (`--bg`, `--accent` #7fbf5b, `--warm`). Параллакс, `.reveal`-анимации появления, адаптив (980/760 px), `prefers-reduced-motion`.

## js/main.js

Параллакс героя (`data-parallax`, rAF), фон шапки при скролле, бургер-меню, плавный скролл с offset, IntersectionObserver для `.reveal` (+ MutationObserver на `#productGrid`), автозапуск видео.

## js/store.js

- `init()` — `GET /api/products`; рендер каталога, футера; демо-баннер.
- Каталог: карточки товаров (галерея — первое фото, затем видео товара
  (если задано `product.video`), затем остальные фото; точки-индикаторы;
  перелистывание полупрозрачными полукруглыми стрелками влево/вправо
  поверх медиа (с зацикливанием) и свайпом влево/вправо на тач-устройствах).
  Видео карточек грузятся лениво — `<video preload="none" controls>`
  с `data-src`, источник проставляется `loadProductVideos()` после события
  `window.load`; нативные `controls` дают перемотку вперёд/назад, паузу и
  смену скорости. Модалка товара (галерея — миниатюры, стрелки, свайп, ←/→;
  видео — `controls`).
- Карточка: бейдж «Предзаказ» и кнопка «Предзаказ» вместо «В корзину», когда
  `product.preorder` (остаток отслеживается и равен 0, оплачиваемый предзаказ
  включён для товара). Когда остаток равен 0, но оплачиваемый предзаказ
  выключен в админке (`product.soldOut`), вместо кнопки — неактивная кнопка
  «Нет в наличии» (в корзину добавить нельзя).
- Лист ожидания: при `product.preorderOffer` (товара нет в наличии) в карточке
  и в модалке товара появляется кнопка «Узнать о поступлении» и подпись
  «Следующая партия — <дата>» — рядом с обычной кнопкой предзаказа с оплатой. Кнопка открывает модалку `#preorderModal`
  (`openPreorder(id,color)`): имя*, одно поле «Как с вами связаться»* —
  телефон, Telegram или e-mail на выбор клиента (подсказка в placeholder,
  канал определяет бэкенд), адрес и комментарий — необязательно, обязательная
  галочка согласия на обработку ПД. Отправка —
  `POST /api/preorder`; после успеха модалка показывает экран «Записали».
- Корзина: `localStorage 'sw_cart'` `[{id,color,qty}]`; drawer.
- Профиль покупателя: `localStorage 'sw_profile'` `{customer,city,deliveryType}` —
  сохраняется на шагах чекаута и подставляется при следующем оформлении
  (`loadProfile`/`saveProfile`).
- Чекаут — модалка, 3 шага:
  1. контакты (имя, телефон, email, комментарий);
  2. доставка — автокомплит города (`/api/cdek/cities`), тип (ПВЗ/курьер), выбор ПВЗ (`/api/cdek/points`) или адрес, авторасчёт (`/api/cdek/calculate`);
  3. оплата — онлайн (Т-Банк) / при получении (наложенный платёж СДЭК), итог,
     **обязательная галочка согласия на обработку ПД** (ссылка на `privacy.html`),
     отметка предзаказа (если в корзине есть позиции без остатка), отправка
     `POST /api/orders` с полем `consent`.
- Ответ заказа: `paymentUrl` → редирект на оплату; `redirect` → страница статуса;
  иначе экран «принято»/«предзаказ оформлен» (`res.preorder`).

## js/cookies.js

Cookie-баннер (152-ФЗ): показывается один раз, пока не нажата «Принять»;
согласие в `localStorage 'sw_cookie_consent'` + cookie (1 год). Ссылка на
`privacy.html`. Подключается на `index.html`, `order.html`, `privacy.html`.

## privacy.html

Политика обработки персональных данных (152-ФЗ): оператор ИП Сурков К.А.,
состав/цели обработки, передача СДЭК/Т-Банк/Re:plain/Метрике, cookie, права
пользователя. Ссылка — в футере и в галочке согласия чекаута.

### Debug-режим (`?debug=1`)

`?debug=1` в URL включает debug-режим. `apiPath()` добавляет `debug=1` ко всем
запросам API; `apiFetch()` парсит ответ и пишет в панель сам запрос, ответ и
серверную трассу (заголовок `X-Sw-Debug`). Фиксированная панель внизу страницы
показывает лог, ловит `error`/`unhandledrejection`, имеет кнопки «Проверить
СДЭК» (`GET /api/cdek/diag`), «Скопировать всё», «Очистить», «Свернуть». При
ошибках СДЭК (города/ПВЗ/расчёт) в debug-режиме показывается настоящий текст
ошибки вместо обобщённого.

## order.html

Страница `/order/success` и `/order/fail`. Читает `?order=`, запрашивает `/api/orders/:id`, показывает статус (оплачено / при получении / демо / ошибка оплаты). `?debug=1` — выводит панель с ответом и серверной трассой.
